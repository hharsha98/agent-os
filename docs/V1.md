# Local v1 — what shipped and what remains

This file is the honest product status for Agent OS **local v1**. It is not a hosted cloud launch checklist.

## In this pass

- Mission Control is the default landing. CLI presence, dashboard chat capability, and live-execution are separate columns.
- Unified Chat shows dry-run / API preview / not-wired labels and does not call Send “Ready” for a dry-run.
- `.env` is loaded at server start (no override of existing process env). Default local port is **8090**.
- Docs and the static gallery dropped recruiter/portfolio framing. github.io remains a gallery, not the runtime.
- Local-agent status no longer claims a prior machine’s OAuth check or “4/4 connected chat”.

## v1 includes

- Clone / `npm ci` / `npm start` install story (default port **8090**, including Docker)
- Dry-run Unified Chat for Claude and Hermes
- Codex API preview when a local key exists
- Workspace sandbox, Memory, Goals, Kanban, Loop
- Execution, install, and public-mode flags default off

## Remaining after this pass

- Cursor Unified Chat routing (intentionally unwired)
- Live tool-using runs (intentionally gated; do not retry ambiguous native runs)
- Agent Builder still needs user-owned Convex/Clerk/Firecrawl/LLM keys for the vendored upstream builder
- Studio image / voice / music stay Not configured
- SEO/Swarm/Overnight Goal Mode are local extras, not the core loop
- `src/App.tsx` is a large unused Hermes control-room shell; not wired as the v1 landing
- No multi-tenant accounts, billing, or studio DNS
- Automated UI/screenshot capture for the gallery (stills may still be missing in git)
- Deeper onboarding wizard beyond Mission Control’s first-run strip
- Mobile-depth QA and Playwright coverage

## Non-goals

- Pretending this is `os.agentic-systems-studio.com` as a live SaaS
- Changing studio DNS
- Shipping fake connected badges for missing CLIs
